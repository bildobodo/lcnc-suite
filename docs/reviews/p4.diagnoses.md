## F4 · The RPM field "sometimes" does not follow the spindle's + / −

**The code (App.vue, `watch([spindleSpeed, isSpinning])`, `spindleIncrease` /
`spindleDecrease`):**
- While the spindle turns, + / − send `spindle_increase` / `spindle_decrease`
  through `fire()`, and the field follows the COMMANDED speed the status
  reports (`spindle[0].speed`, status_runtime.py) — only where that value is
  `> 0`, and only while no operator value is pending (`rpmPending`, BG-27).
- `fire()` drops a command while the per-tab busy latch is set
  (`DEFAULT_COOLDOWN_MS` 200 ms after the previous command; `spindle_increase`
  has no own cooldown). The drop is said only in the browser console
  (`[fire] … dropped: another command is settling`) — no hint at the
  control.
- Stopped, + / − change the preselection locally; with `spindleManual`
  closed they return without a word.

**Candidates (none proven):**
1. Taps faster than 200 ms apart while turning: every second tap is dropped
   silently — "sometimes" matches a tap rhythm. Decides it: the browser
   console during quick taps (or a hint recorder), the gateway trace's
   `spindle_increase` count against the taps.
2. Reverse: `spindle[0].speed` is signed in LinuxCNC (negative in M4 —
   to be read in emcmodule.cc / the canon, not assumed); the `> 0` guard
   would then never mirror in Rev. The operator saw no Fwd/Rev split, which
   speaks against this as the only cause.
3. A typed value pending (BG-27) keeps the field by design until the
   controller takes it.
4. Stopped with `spindleManual` closed (busy overlay, a gate) — silent.

**Reproduction (VM sim):** spindle Fwd, then Rev; + / − at 1 s and at 100 ms
intervals; record the console and the trace. A fix plan follows the result
(likely: the dropped tap answered at the control, and the sign handled).

## F13 · The Resume hold's fill bar starts, then jumps to full

**The code (Btn.vue `.b.holding::after`, holdGesture.ts):** the fill is a CSS
animation (`hold-fill`, `--hold-duration`, `transform: scaleX`) that starts
when the `.holding` class is first STYLED — at the next rendering
opportunity after the press; the action is fired by the hold's JS timer
(`HoldTracker`, set at the press, `holdMs`). The two clocks are separate by
design ("the animation is visual only"). A main-thread delay between the
press and the first frame starts the animation late by that delay, while the
timer still fires at its time — the action fires with the bar short of full
and the bar then ends ("jumps"). The stall guard (`HOLD_STALL_MS` 150) bounds
that delay for a hold that fires: the jump is at most the last ~30 % of the
bar.

**Open:** whether the machine-day jumps match main-thread delays at the
press. P3's `browser.stall` and `browser.hold.refused` (with `gap_ms`) record
exactly these delays on the next machine day. **Fix direction (not in P4):**
drive the fill from the hold's own start (a negative `animation-delay` of the
elapsed time at the first frame, or the transform set from the hold timer),
so the bar and the fire share one clock.

## F21 · A faint periodic repaint in the Tools table around the open tool card

**The code:** the card (`.toolHoverPreview`, teleported, `position: fixed`,
box-shadow) holds a `ToolPreview` WebGL canvas that renders on mount and on a
change of its inputs only — no animation loop. The table rows re-render on a
re-read (`toolTableVersion` → `fetchTools`) and on `currentTool`. Nothing in
the Tools tab animates on a ~0.5 s period; the app's periodic animations are
the flashes on ONE 0.6 s clock (`flashClock.ts`: the E-Stop Reset, the state
banner) and the probe status dot's pulse (`statusPulse`, 0.8 s alternate) —
the Tools tab's head shows that dot (App.vue).

**Candidates (none proven):** the compositor repainting the region under or
around the fixed card when a pulse/flash elsewhere invalidates a shared
layer; a re-read loop (excluded at `70106a7e`: nothing bumps the version
periodically). **Reproduction:** VM sim, T99 loaded, the card open, Chromium
paint flashing on and a performance trace — which layer repaints, at what
period, and whether the probe dot's pulse or a flash coincides.

P4-3 already closes the card on a tab switch, an outside press and a scroll,
which ends the case the operator met (the card left open).
