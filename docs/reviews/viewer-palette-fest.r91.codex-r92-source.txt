5488: /*! convert_tool_change
5489: 
5490: Returned Value: int (INTERP_OK)
5491: 
5492: Side effects:
5493:    This makes function calls to canonical machining functions, and sets
5494:    the machine model as described below.
5495: 
5496: Called by: convert_m
5497: 
5498: This function carries out an M6 command, which changes the tool.
5499: If M61 is called, the toolnumber gets changed (without causing an actual toolchange).
5500: 
5501: When the CHANGE_TOOL call completes, the specified tool should be
5502: loaded.  What this means varies by machine.  According to configuration,
5503: the interpreter may also issue commands to do one or more of the
5504: following things before calling CHANGE_TOOL:
5505: 
5506: 1. stop the spindle
5507: 2. move the quill up (Z to machine zero, like G0 G53 Z0)
5508: 3. move the axes to reference point #2 (like G30)
5509: 
5510: Further, the interpreter makes no assumptions about the axis positions
5511: after the tool change completes.  This state is queried and the internal
5512: model is resynched before the program continues.  This means CHANGE_TOOL
5513: itself can also issue motion (and it currently may, according to
5514: configuration).
5515: 
5516: This implements the "Next tool in T word" approach to tool selection.
5517: The tool is selected when the T word is read (and the carousel may
5518: move at that time) but is changed when M6 is read.
5519: 
5520: Note that if a different tool is put into the spindle, the current_z
5521: location setting will be incorrect. It is assumed the program will
5522: contain an appropriate USE_TOOL_LENGTH_OFFSET (G43) command before any
5523: subsequent motion.  It is also assumed that the program will restart the
5524: spindle and make new entry moves if necessary.
5525: 
5526: */
